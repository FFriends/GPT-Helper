# Дополнительная установка Coop для GPT Helper

[English](README.md)

Этот необязательный помощник скачивает и настраивает оригинальный **Coop v0.6.0**. Установка плагина
GPT Helper **не устанавливает** Coop и не создаёт VM. Здесь нет готового образа, копии вашей текущей
среды, среды для телефона или автоматического разрешения на её использование.

## Требования и границы

- Linux **x86_64**, Python **3.10+**, доступный работающий `/dev/kvm` и sudo для настройки Coop.
- Windows: **PowerShell 7**, уже установленный дистрибутив Linux x86_64 в WSL **2**, Python 3.10+
  внутри него и работающий вложенный KVM. Скрипт выбирает `Ubuntu-24.04` и его обычного пользователя
  по умолчанию, не навязывает root. Наличия WSL недостаточно: совместимость зависит от хоста и ядра.
- Помощник не поддерживает нативный Windows, macOS, ARM и телефоны. Он не устанавливает WSL,
  не включает виртуализацию, не меняет политику PowerShell и не исправляет права KVM автоматически.
- Для действий с изменением состояния нужен `--confirm`. Для агента этот флаг **не заменяет явное
  разрешение пользователя в рамках задачи** на установку, работу с VM, передачу файлов и команды.

## Получение файлов

Скачайте весь [ZIP GPT Helper](https://github.com/FFriends/GPT-Helper/archive/refs/heads/main.zip)
и распакуйте либо клонируйте репозиторий. Сохраните файлы этой папки рядом, затем перейдите в
`plugins/gpt-helper/coop` внутри распакованного/клонированного репозитория. Вариант через Git:

```sh
git clone https://github.com/FFriends/GPT-Helper.git
cd GPT-Helper/plugins/gpt-helper/coop
```

## Linux / внутри WSL

Используйте нужного пользователя Linux. Перед подтверждением проверьте каждую операцию:

```sh
python3 -I coop_helper.py install --confirm
python3 -I coop_helper.py check
python3 -I coop_helper.py setup --confirm
```

`install` скачивает официальный архив закреплённой версии, сверяет SHA-256, устанавливает `coop`,
`coop-proxy`, исходную лицензию и ограниченную конфигурацию. VM не создаётся и не запускается.
`check` проверяет локальные файлы, флаги CLI, часть зависимостей и API KVM; загрузку VM и сеть
он не тестирует. При ошибке остановитесь; не заменяйте изоляцию запуском проекта на хосте.

**`setup` изменяет хост:** Coop может запросить sudo, установить недостающие пакеты хоста, скачать
Firecracker и ядро, монтировать файловые системы и собрать rootfs через chroot. Образ содержит
Docker, GitHub CLI, Claude Code и Codex. Помощник не запускает сессию агента, но сам образ
не является «средой без агентов». Скачивание использует сеть. Читайте запросы Coop: разрешение
установить плагин GPT Helper само по себе не разрешает эти действия.

Подготовьте **отдельную проверенную копию проекта** только с разрешёнными файлами. Замените путь
ниже её абсолютным Linux-путём; в WSL также подходит конкретная папка проекта `/mnt/c/...`:

```sh
python3 -I coop_helper.py up --name sample-task --project /absolute/path/to/reviewed-project --confirm
python3 -I coop_helper.py exec --confirm --name sample-task -- uname -a
python3 -I coop_helper.py status
python3 -I coop_helper.py stop --name sample-task --confirm
```

`up` требует **новое имя**, создаёт VM с копией проекта, исключает `.git`, пропускает передачу
авторизации/настроек агентов и обработку devcontainer, затем проверяет доступность гостя. Существующие
имена запрещены; команды перезапуска нет. `exec` выполняет указанную команду внутри VM. `status`
показывает локальные записи об экземплярах, **не текущую работоспособность**. `stop` сохраняет диск VM.

## Windows / PowerShell 7

Из этой же папки используйте скрипт вместо `python3 -I coop_helper.py`:

```powershell
.\Coop.ps1 -CoopArguments @('install', '--confirm')
.\Coop.ps1 -CoopArguments @('check')
.\Coop.ps1 -CoopArguments @('setup', '--confirm')
.\Coop.ps1 -CoopArguments @('up', '--name', 'sample-task', '--project', '/absolute/path/to/reviewed-project', '--confirm')
.\Coop.ps1 -CoopArguments @('exec', '--confirm', '--name', 'sample-task', '--', 'uname', '-a')
.\Coop.ps1 -CoopArguments @('status')
.\Coop.ps1 -CoopArguments @('stop', '--name', 'sample-task', '--confirm')
```

При необходимости добавляйте `-Distribution 'YourDistro'` и `-LinuxUser 'youruser'` ко всем вызовам.
Скрипт может запустить выбранный дистрибутив WSL: это хост Coop, **не** гостевая VM Coop.
Если PowerShell блокирует скрипт, проверьте свою политику; помощник её не обходит.

## Безопасность, хранение и ограничения

- Данные находятся в `~/.local/share/gpt-helper-coop/v0.6.0/` выбранного пользователя Linux:
  отдельные конфигурация, бинарники, данные, Firecracker и ядро. Существующая `~/.coop` не используется.
- Существующая папка установки не перезаписывается. Прерванная установка или неудачная операция VM
  может оставить файлы/ресурсы для проверки; автоматического удаления и запуска на хосте при ошибке нет.
- Каждый вызов Coop получает ограниченное окружение. Передача GitHub-авторизации, копирование
  настроек агентов, дополнительные переменные и фоновые проверки обновлений отключены.
  С изменённой конфигурацией помощник отказывается работать.
- Проверка проекта отклоняет некоторые очевидные пути с секретами и символьные ссылки, но **не
  гарантирует отсутствие секретов**. Проверьте все файлы сами. VM не гарантирует нулевой риск или запрет сети.
- Нет автоматического возврата файлов, обновления, перезапуска и удаления. Проверяйте гостевые
  изменения перед ручным переносом нужных файлов; сохраняйте посторонние правки на хосте.
  Не публикуйте диски VM, ключи и локальное состояние.
- При разработке выполнены только офлайн-проверки; **реальная установка и работа VM для этого
  пакета не тестировались**. Версия CLI закреплена, но не все дальнейшие скачивания upstream setup.

Повторная офлайн-проверка из этой папки на Python 3.11+: `python3 -m unittest -v test_coop_helper`.
В тестах сеть, процессы и KVM заменены тестовыми объектами; Coop не устанавливается.
Код помощника GPT Helper распространяется по MIT; скачанный Coop сохраняет лицензию Apache-2.0.
